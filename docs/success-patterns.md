# Success patterns to replicate structurally

The objective is not originality-first. It is evidence-first iteration. Replicate mechanics and commercial structures; never copy proprietary code, assets, names, maps, characters, audio, thumbnails, listing copy or brand identity.

## 1. One-sentence core loop

Current hits are legible before a player joins: solve a murder round, grow/collect, roleplay a life, survive nights, progress combat. The MVP must be explainable in one sentence and produce value in the first minute.

## 2. Persistent visible progress

Collections, upgrades, ranks, plots, vehicles, homes, mastery and streaks make progress inspectable by both the player and nearby players. Visibility creates social proof without requiring chat.

## 3. Social adjacency before forced teamwork

Brookhaven-style roleplay and Grow-a-Garden-style organic social play allow players to coexist, compare, help and show off. Do not make another human a hard dependency for basic progress. Add optional cooperation with a better payoff.

## 4. Shareable moments

Create events that naturally produce stories: close calls, funny role failures, rare discoveries, coordinated rescues, perfect driving streaks, team records. Prefer positive drama over destructive loss.

## 5. Learning hidden inside fantasy

The Play to Learn winner uses chemistry reactions as battle/exploration mechanics. Our learning game should make traffic rules and arithmetic the means to succeed at an appealing social-city fantasy, not the reason the user is asked to play.

## 6. Time-saving creator tools

Paid plugin demand clusters around painful, repeated Studio jobs: data editing, animation, UI authoring, rigging and other workflow acceleration. RevenueOS should reduce monetization setup/QA from hours to minutes and show concrete before/after value.

## 7. Frequent small updates

The autonomous system should ship one measurable hypothesis at a time. Each release owns one KPI, has a canary and can be rolled back.
